# 3dvault named collection consideration

The first useful 3dvault promotion pass recovered named OpenSea collections from escaped locale data, then deeply sampled their token metadata and validated any model URLs as binaries.

## Materialized collection-level considerations

- **VOID - Voyagers of Imma Degen** — Ethereum `0x3137e02341a4acbf01a02cfb60ccc194c3452756`; holder-gated VRM delivery confirmed at collection level. 38 sampled public model URLs fetched as valid GLB 2.0 but are not VRM. OpenSea states VRM/GLB/FBX are supplied through the linked 3D Vault, so public GLB evidence and private VRM delivery remain distinct.
- **VOID - Visitors of Imma Degen** — Ethereum `0xdb55584e5104505a6b38776ee4dcba7dd6bb25fe`; collection description confirms a metaverse-ready avatar/3D model for each VOID. Native VRM delivery remains under verification.
- **The WynLambo** — Ethereum `0x414c5e3716bcec4b2373108b187914215695627a`; collection description confirms full 3D NFTs. Native VRM delivery remains under verification.
- **CLONE X - X TAKASHI MURAKAMI** — Ethereum `0x49cf6f5d44e70224e2e23fdcdd2c053f30ada28b`; holder-gated official 3D files and official VRM conversion tooling are known, but native per-token VRM was not observed in sampled NFT metadata.

These are collection-level consideration statuses, not a relaxation of binary VRM validation. A public model file is called VRM only after the GLB 2.0 container and `VRM`/`VRMC_vrm` extension are directly verified.
